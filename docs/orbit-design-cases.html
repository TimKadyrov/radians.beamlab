The Three Orbit Cases

A non-GSO filing must say how each shell of the constellation holds its path over the Earth. The calculation of equivalent power flux-density (epfd) in Rec. ITU-R S.1503-4 simulates the orbits as filed, and there are three ways to file them: the three orbit cases. On the Orbit Design tab you choose one case per shell, and the tab fills in the fields that case files.

Choosing a case

Each shell takes one case. Choose it on the Constellation sub-tab, under Station-keeping case. Two questions decide it, asked in this order:

  • Case 1 — free drift. The system does not use station keeping to hold a repeating ground track, the line each satellite traces over the Earth. The operator lets the orbit drift. The filing declares nothing about the drift, and the EPFD calculation adds a correction of its own. Without station keeping a shell is Case 1, whatever else it files.
  • Case 2 — station-kept repeating, the default. The operator holds the ground track so that it repeats within a promised tolerance. The filing declares the repeat period and the tolerance.
  • Case 3 — station keeping with supplied precession. The operator holds the track as in Case 2, and the administration also supplies the rate at which the orbit’s plane turns. The filing declares the repeat period, the tolerance and the rate. The EPFD calculation turns the plane at that rate instead of its own.

The Station-keeping cases sub-tab shows all three side by side for the selected shell, so you can compare them on the same orbit before you choose. Cases 1 and 3 file the target orbit exactly as you entered it on Start here. By default Case 2 files the altitude where the selected repeat closes by itself. Cases 2 and 3 both need a repeat from the Repeat solver.

The chosen case fills the station-keeping columns of the SNS orbit table that the Constellation sub-tab previews: keep, keep_rnge, rpt_prd and precess. Save design stores the case with the shell, and the SNS v10 builder writes it into the notice. Save design refuses a Case 2 or Case 3 shell that has no repeat selected or whose keep_rnge is out of bounds. It also refuses a Case 3 shell whose rate turns against its inclination, or whose typed rate misses the repeat by more than keep_rnge a cycle (see Case 3 below).

Keep all shells repeating or all not. Case 2 and Case 3 shells both count as repeating. When some shells declare a repeat and others do not, the shells list on Start here warns you.

Tech · the filed fields

Case 1 files f_stn_keep='N' and f_precess='N'. Case 2 files f_stn_keep='Y', keep_rnge (deg) and rpt_prd_dd/hh/mm/ss. Case 3 files the same as Case 2 plus f_precess='Y' and precession. These are columns of the SNS v10 orbit table, one row per plane. precession is the rate’s magnitude in degrees per day, format 999.99, 0 or more. Its direction is not on file: it is the one the inclination implies, west below 90°, east above, none at exactly 90°. The tab works in signed deg/s (the precession box and the preview’s precess column); the filing carries the magnitude × 86 400, rounded to 0.01 deg/day, and the Case 3 panel shows that value with the way it turns.

Rec. ITU-R S.1503-4 §B3.1 defines the parameters: DoesRepeat with W_delta, AdminSuppliedPrecession with ORBIT_PRECESS. §D6.3.6 and Figure 52 combine them into the three cases, station keeping first, and give each case’s propagation, eqs (45)–(53). The SRS orbit table in the Attachment to Part B defines the precession field. The mixed-shells warning cites §A2.4 and §B5.1.

Why the cases exist

The EPFD calculation is a simulation. It replays the satellites’ motion over a run and adds up the interference that reaches a victim earth station. The result is fair only if the run sees the constellation in every position it can take, not just the positions that happened to occur during the run.

Satellite tracks do not stand still. The Earth turns under the orbit on every lap. The Earth’s equatorial bulge also turns the orbit’s plane slowly: westward for an orbit inclined below 90°, eastward above. So each lap’s track lands further west than the last, and at an arbitrary altitude the pattern never comes back to where it started. The filing says what the operator does about that: lets it run (Case 1), holds the track (Case 2), or holds the track and supplies the rate at which the plane turns (Case 3).

The westward step

Watch a satellite cross the equator heading north, then watch its next northbound crossing one lap later. The second crossing lands a fixed distance west of the first. This westward step per lap is what all three cases work from. The Case 1 panel prints it as S_pass.

The tab computes the step from the target orbit on Start here: Altitude (km), Inclination (deg), the orbit’s tilt, and Eccentricity, how stretched it is (0 is circular).

Tech · the westward step
n̄  = n₀ [1 + 1.5 J₂ (Re/p)² (1 − 1.5 sin²i) √(1−e²)]
Ω̇  = −1.5 J₂ (Re/p)² n̄ cos i     ω̇ = 1.5 J₂ (Re/p)² n̄ (2 − 2.5 sin²i)
T_nodal = 360 / (ω̇ + n̄)     S_pass = (ω_e − Ω̇) · T_nodal

The J2 secular rates of Rec. S.1503-4 §D6.3, with ω_e the Earth’s rotation rate. Ω̇ is the J2 nodal regression, the slow turning of the plane; T_nodal is the time between two northbound equator crossings. The app’s propagator integrates the same rates, so the tab’s numbers are what its simulations do.

CASE 1Free drift — the calculation adds its own correction

The operator does nothing about the drift. The ground track slides west forever and never repeats.

That is a problem for the EPFD calculation, which has to stop somewhere. Cut a drifting track off after any finite time and some longitudes have been visited many times while others were never visited at all. The result would then depend on where the run happened to start and stop.

So S.1503-4 has the calculation add a small extra drift of its own, an artificial precession. It is sized so that a chosen number of laps, NOrbits, spreads the crossings evenly around the equator and then closes. It is a device of the simulation, not a property of the satellite: the filing declares nothing for it.

What you set, in Case 1 — free drift (informational) on the Station-keeping cases sub-tab:

  • victim beamwidth (deg): the 3 dB beamwidth of the victim earth station’s antenna. When you enter it, the tab derives NOrbits from it at your target altitude. Leave it empty to set NOrbits yourself.
  • NOrbits (run): the number of laps in the run, 288 by default.

The panel prints the westward step, the even grid step, the correction rate, the run length in days, and the spacing the run actually measures, which is not the even grid step (see the second box below). Nothing in the panel is filed. The saved design keeps NOrbits, and this app’s simulations of the design add the same correction.

Tech · the Case 1 numbers
S_grid  = 360 · floor(NOrbits · S_pass / 360) / NOrbits
rate    = (S_grid − S_pass) / T_nodal   (added to the node rate)
run     = NOrbits · T_nodal
φ = θ_3dB/2 − arcsin[Re/(Re+h) · sin(θ_3dB/2)]
NOrbits = ceil(180 / S_req),  S_req = 2φ / N_tracks,  N_tracks = 16

Rec. S.1503-4 §D6.3.2, Steps 8–11, for the correction. For NOrbits, φ is the half-angle, seen from the Earth’s centre, of the victim beam’s crossing at the target altitude h (Part D eq. (3)); S_req and NOrbits follow §D4.6.2, Steps 5–7, with N_tracks from §D4.5. The panel prints the rate in deg/s and rad/s.

Tech · the measured spacing

Followed literally, Steps 8–11 add the rate to the node’s own drift with a sign that moves the step away from the even grid instead of onto it. Each lap then steps 2·S_pass − S_grid instead of S_grid: the same correction, applied the other way. The difference from the grid step stays within two grid cells. The app’s propagator follows the steps as written, so the panel prints this measured spacing beside S_grid.

filed: station keeping = no  ·  precession = no

CASE 2Station-kept — a promised, repeating track

The operator uses station keeping, small manoeuvres that hold the orbit in place, to make the ground track repeat. After a whole number of laps every satellite retraces the same lines over the Earth, staying within a promised longitude tolerance either side of them.

The filing says two things: how long one repeat takes (the repeat period) and how wide the tolerance is (the keep range). The EPFD calculation does not force the orbit onto the declared repeat. It flies the filed orbit as it is, with the natural drift of its altitude and inclination, and sweeps each satellite across the tolerance band over the run, because within the promise the system may be anywhere in it. The repeat period only sets how long the run lasts.

A track repeats by itself only at special altitudes: it closes after k laps when k westward steps add up to exactly m whole turns of the Earth. At an arbitrary altitude they almost never do. A real satellite there would correct the small natural drift by station keeping, and that is what the tolerance is for. The calculation makes no such correction, so the altitude you file decides whether the simulated track repeats. By default the tab files the altitude where it does.

What you set.

  • 1 · Altitude mode, on the Repeat solver sub-tab. adjusting altitude, the default, files the selected candidate’s exact closing altitude, where the filed orbit repeats by itself. fixed altitude files your target altitude. The calculation then flies that orbit’s natural drift every cycle of the run, on top of the keep_rnge sweep; the candidate grid shows it per cycle as drift@target.
  • The repeat, k laps in m days: select a row of the candidate grid. At a fixed altitude you can also type Orbits (k) and Nodal days (m) under 2 · Declare a period of your own; the pair starts on the nearest repeat.
  • keep_rnge (deg), the tolerance, on the Case 2 panel or under 3 · Tolerance (keep_rnge) on the Repeat solver. Both fields hold the same value, 0.5 by default. The tolerance is your promise, not a solved value: the tab only checks it against its bound.

The Case 2 panel prints the filed fields, the track spacing and the repeat pair. At an adjusting altitude it gives the exact closing altitude. At a fixed altitude it gives the drift the calculation flies every cycle, and how many cycles (and days) a real satellite’s drift would take to cross your keep_rnge: the time between its station-keeping corrections.

The bound. The tracks of a k-lap repeat cross the equator 360/k degrees apart. Each track’s tolerance band must stay clear of its neighbours, so keep_rnge must be less than half that spacing. The grid shows the limit as max keep_rnge.

The map. The Repeat solver sub-tab propagates one declared cycle of the selected candidate through the app’s propagator and draws its ground track. The dot marks where the track starts and the ring where it ends; track closure after one cycle prints the gap between them. At an adjusting altitude the two coincide. At a fixed altitude the gap is the natural drift per cycle, the same drift the EPFD calculation flies every cycle of its run.

Several shells. One repeat period must hold for every satellite of the constellation. The shells list shows the constellation repeat, the least common multiple of the shells’ declared periods, and warns when it runs past 100 days. Harmonize rpt_prd, on the Constellation sub-tab while the case is Case 2 or Case 3, declares that common period on every shell. It needs every shell to be Case 2 or Case 3 with a repeat selected. Changing a shell’s repeat, case or altitude mode clears it.

Tech · the Case 2 numbers
repeat after k laps  ⇔  k · S_pass(a) = 360 · m,  gcd(k, m) = 1   (solved for the altitude a near your target)
drift@target = k · S_pass(target) − 360 · m   (per cycle)
rpt_prd = k · T_nodal at the filed altitude (a by default, or the target), in whole seconds
spacing = 360/k     0 < keep_rnge < 180/k
cycles for a real satellite’s drift to cross keep_rnge = keep_rnge / |drift@target|
harmonized rpt_prd = LCM of every Case 2 and Case 3 shell’s own period
Ω(t) = Ω₀ + Ω̇·t + keep_rnge·(2t/T_run − 1)

Filed as f_stn_keep='Y', keep_rnge and rpt_prd_dd/hh/mm/ss. The calculation moves the filed orbit on its own J2 rates and sweeps the ascending node, where the orbit crosses the equator heading north, linearly across the band: from −keep_rnge at the start of the run to +keep_rnge at its end (Rec. S.1503-4 §D6.3.6, eqs (48)–(50)). Nothing holds the orbit on the declared repeat: filed at the target altitude, the track keeps its drift@target every cycle. The declared period sets only the run length, T_run = N_run · P_repeat, and keeps the time step from dividing it exactly (§D4.6.1). §B3.1 (DoesRepeat, W_delta); §A2.4 for one repeat period for all satellites.

filed: station keeping = yes  ·  keep range (deg)  ·  repeat period (dd/hh/mm/ss)

CASE 3Station keeping with a supplied rate

Case 3 is station-kept too. The operator holds a repeating ground track within a keep range, as in Case 2, and the administration also supplies the rate at which the orbit’s plane turns. Rec. S.1503-4 §D6.3.5 describes that rate as supplied “to ensure a repeat ground track”.

With a supplied rate the EPFD calculation uses a simpler orbit model. It turns the plane at the supplied rate instead of the rate the Earth’s bulge would give, keeps the orbit fixed within its plane, and moves the satellite at the pace of a plain Keplerian orbit, as if the Earth were a point mass. It still sweeps each satellite across the keep range over the run. The supplied rate is what makes this simple model repeat.

What you set.

  • The repeat, on the Repeat solver, as for Case 2. Case 3 needs one: without it the Case 3 panel asks for a repeat and Save design refuses the shell.
  • keep_rnge (deg), the same tolerance, with the same bound, as Case 2.
  • precession (deg/s), in Case 3 — station keeping with supplied precession on the Station-keeping cases sub-tab, signed: negative turns the plane west, positive east. Leave it empty and the tab declares the rate that closes the selected repeat at your target altitude under this model. Type a rate to supply your own; it must close the repeat too (see below).

Case 3 always files your target altitude; the altitude mode on the Repeat solver only changes how you pick the repeat. Its repeat period is k laps of the plain Keplerian orbit at that altitude, slightly different from Case 2’s cycle@target. The panel prints the filed fields, the rate in deg/s, the degrees per day on file and the way the rate turns, where the rate comes from, and the plain J2 rate of your target orbit for comparison. If the text in the box is not a number, the panel says so and the shell files the closing rate.

The filing carries the size of the rate; the inclination gives its direction. The precession field holds the rate’s magnitude in degrees per day, 0 or more. The direction is the one the inclination implies, as for the natural turning of the plane (Rec. S.1503-4 eq (21)): west for a prograde orbit, inclined below 90°, east for a retrograde one, inclined above 90°. A polar orbit, at exactly 90°, implies none. So a rate can be filed only when it turns the way its inclination does. A rate turning against it, east on a prograde orbit or west on a retrograde one, cannot be filed, and neither can any rate other than zero at exactly 90°. Then the Case 3 panel says so, Save design refuses the shell and the SNS v10 builder refuses the design. File such an orbit as Case 2.

With the tab’s defaults, 1200 km and 53°, the rate that closes 13 orbits in 1 day is −3.45°/day: it files as 3.45°/day, turning west, as a prograde orbit does. A Sun-synchronous orbit at 561 km, inclined 97.64° and circular, repeats after 15 orbits in 1 day; that repeat closes by itself at 560.99 km. Its closing rate is +0.53°/day: it files as 0.53°/day, turning east, as a retrograde orbit does. That is not the +0.9856°/day the plane really turns, because the model moves the satellite at the plain Keplerian pace.

The default rate can still come out turning the wrong way, because it also takes up the selected repeat’s drift at your target altitude (see the box below). With the defaults, the repeat of 105 orbits in 8 days closes at +0.02°/day: east on a prograde orbit, so it is refused. The Sun-synchronous orbit at 550 km, with the same 15-orbit repeat, closes at −0.33°/day: west on a retrograde orbit, refused too. A repeat that closes nearer the target, 15/1 at 561 km in that example, turns the right way.

A typed rate must close the repeat. The Case 3 model repeats only at the closing rate, so a rate you type is checked against it. The panel prints how far the typed rate leaves the track from closing the selected repeat each cycle. When that is more than keep_rnge, the tolerance cannot hold even for one cycle: the panel says the rate cannot be filed and Save design refuses the shell. The default rate is the closing rate and is not checked. An earlier version of the Recommendation, S.1503-2, asked the software to check a supplied rate for self-consistency with the other inputs; S.1503-4 no longer does, so this check is the app’s own. For example, typing the Sun-synchronous orbit’s physical rate, 1.1407E-5 deg/s (0.9856°/day), for the 561 km example leaves the track 0.458° from closing each cycle: inside the default keep_rnge of 0.5°, refused at 0.4°.

Elliptical orbits. Case 3 holds the perigee fixed within the orbit’s plane. A real elliptical orbit’s perigee turns at the rate the Earth’s bulge gives it, which is zero only at the critical inclinations, 63.43° and 116.57°. For an elliptical orbit the Case 3 panel prints that real rate in degrees per day, to show what Case 3 leaves out; at a critical inclination it says the real perigee is still, as Case 3 holds it.

Tech · the Case 3 numbers
D = ω_e − m · n₀ / k   (default rate, at the target, rounded to 0.01°/day)
rpt_prd = k · 2π / n₀, in whole seconds,  n₀ = √(μ/a³)
precession field = |D| (deg/s) · 86 400  (deg/day, ≥ 0, format 999.99);  direction = −sign(cos i)
fileable  ⇔  D = 0, or sign(D) = −sign(cos i)   (any D ≠ 0 refused at i = 90°)
typed-rate miss per cycle = (D_typed − D_exact) · k · 2π / n₀;  refused when |miss| > keep_rnge
Ω(t) = Ω₀ + D·t + keep_rnge·(2t/T_run − 1)    ω(t) = ω₀    M(t) = M₀ + n₀·t
real apsidal rate ω_r = 1.5 J₂ (Re/p)² n̄ (2 − 2.5 sin²i)   (0 at 63.43° and 116.57°)

Rec. S.1503-4 §D6.3.6, eqs (51)–(53): the supplied rate D replaces the J2 nodal term, the argument of perigee is held and the mean anomaly advances at the point-mass mean motion n₀. So k orbits take 2πk/n₀, and the track closes after m nodal days when the node turns at D. The tab rounds the default rate to the 0.01 deg/day the field carries, so the rate flown and the rate filed agree. The plain J2 rate printed for comparison is −1.5 · n₀ · J₂ · (Re/p)² · cos i, with p = a(1 − e²). Filed as f_stn_keep='Y', keep_rnge, rpt_prd_dd/hh/mm/ss, f_precess='Y' and precession: §B3.1 (DoesRepeat, W_delta, AdminSuppliedPrecession, ORBIT_PRECESS) and the SRS orbit table in the Attachment to Part B.

Why the direction is applied when the field is read. The supplied rate enters the propagation only as a turn of the node about the Earth’s axis: Rz(Ω + D·t) Rx(i) Rz(ω) = Rz(D·t) [Rz(Ω) Rx(i) Rz(ω)], the rotation of §D6.3.3 eqs (34)–(43) with the node of eq (52). The inclination inside the matrix does not change which way the node turns, so a magnitude taken as it stands would always turn it east. The examination software applies the direction the inclination implies, −sign(cos i) as in §D6.3.2 eq (21), when it reads the field.

The default rate also takes up the selected repeat’s drift at your target altitude. In low orbit it moves by roughly 0.08°/day for each kilometre between the target and the repeat’s exact altitude: the Sun-synchronous example gives +0.45°/day at 560 km and −0.33°/day at 550 km, for the same 15-orbit repeat. A repeat that closes far from the target can therefore give a rate turning against the inclination, which cannot be filed.

The typed-rate check compares the typed rate with the exact closing rate before rounding, D_exact, over Case 3’s own period. S.1503-2 §D.6.3.4, Note 1, asked for a self-consistency check of a supplied rate; S.1503-4 §D6.3.5 carries no such note. The elliptical note compares the perigee Case 3 holds, eq (51), with the real J2 apsidal rate of §D6.3.2 eq (22) at the target orbit; the panel treats a rate below 0.005 deg/day as a critical inclination.

filed: station keeping = yes  ·  keep range  ·  repeat period  ·  precession = yes, magnitude in deg/day

From your orbit to the filing

All three cases start from one computation. Three numbers describe the orbit, the drift computation gives its lap period and westward step, and each case adds its own inputs to produce its fields.

Copy case summary (text), below the three panels, puts the three previews on the clipboard as plain text, for notes or mail. With no repeat selected it copies Case 1, which stands without one, and the Case 3 panel, which then asks for a repeat. For machine-readable output, use Save design and the SNS v10 builder.
