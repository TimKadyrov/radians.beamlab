Inside the R Set

The R set is the filing's promise about how the system points and schedules — the operating constraints the EPFD examination enforces alongside the pfd and e.i.r.p. masks. This page explains what it declares (and deliberately does not), how the examination reads it, and the two ways the designer authors it.

What the R set declares

Not a watt of it is about transmission. Powers, e.i.r.p. and the shape of the emissions are enveloped by the pfd and e.i.r.p. masks; the R set declares the pointing and scheduling discipline the operation keeps — the promises that decide when a non-GSO satellite may serve at all, and how many may do so together.

quantitythe promise
min_elevno link below this elevation (per latitude and azimuth; header elsewhere)
min_excludeno transmission inside this GSO-arc angle (per latitude, per orbit)
max_co_freqat most this many co-frequency satellites toward one cell (per latitude)
max_co_freq_satat most this many co-frequency beams from one satellite
min_durationa link, once made, is held at least this long (per latitude; header elsewhere)
min_angle_at_sat / _esco-frequency links stay at least this far apart in angle
es_density · es_distancehow densely the system's earth stations deploy, and how far apart
es_lat_min / _maxthe latitude span the earth stations occupy

The header quantities are single numbers; four of them can also be declared as per-latitude arrays that refine the promise where the geometry differs — a polar system's elevation floor at the equator is not its floor at 70°.

How the examination reads it

Tech · header vs arrays

Where an array covers the earth station's latitude, the array row governs; elsewhere the header value fills in, and an absent header is permissive — no constraint is assumed on the operator's behalf. Per Part B of Recommendation ITU-R S.1503-4's R table, min_elev, max_co_freq and min_duration are read at the nearest latitude row, while min_exclude is read by linear interpolation between rows; the minimum angles are taken as zero when not provided.

Two consequences are worth carrying around. A quantity you leave undeclared costs you nothing at examination time but promises nothing either; and an array only reaches as far as its rows — outside the declared latitude span the header (or permissiveness) takes over. Declare what the operation actually does, where it actually does it.

Two ways to author it

Manual entry is for values known a priori — copying an existing filing, or writing a deliberately conservative envelope. Every header quantity is a box, every array a few lines of text, and each field's tooltip is its parameter card.

Derive from simulation is the intended path when the declarations are not known: point at the orbit design document and the operation profile — the profile is required, because it is the system under measurement, transmission basics included — and fly the operation under the scheduler. Everything every granted link actually did is then enveloped into a declared set.

What the derivation writes

  • Measured minima become floors — the smallest link elevation per latitude band, floored to 0.1°; the smallest GSO offset per band, declared as an exclusion row only where an exclusion actually shaped operations. A near-zero floor that no rule enforced is geometry, not a promise, and is not declared.
  • Measured maxima are carried — the most co-frequency links any cell received per band, the most one satellite carried, the smallest angular separations observed between simultaneous links.
  • The deployment comes from the geography — the served-latitude span, the cell pitch as es_distance, and es_density as one station per cell-pitch square.
  • Quantities never observed stay undeclared — the deriver writes arrays, not guesses; a header it did not measure is left empty rather than invented.

The derived set is usually tighter than the profile's own rules, because a real operation rarely rides its limits: a 10° elevation gate produces links at 10.3°, and 10.3° is what gets declared. That is the same doctrine the pfd and e.i.r.p. masks follow — declarations as envelopes of the simulated truth.

Tech · the writer's encoding rules

Export enforces the R-set XML conventions: min_duration is never written as 0 (omit it to select the classic algorithm), min_angle_at_es is rejected when min_duration is declared, and es_density / es_distance must be declared together or both omitted.

Where the set goes

The exported XML registers in the SNS builder as an f_mask R row of the dataset. The JSON round-trips the designer — and the Simulation runner accepts it as the optional alternative gate source: the scheduler obeys the declared constraints instead of the profile's enforced gates, so the same truth payload can be flown under its own discipline and under the declared one, and the two CDFs show what the declaration costs or allows.
